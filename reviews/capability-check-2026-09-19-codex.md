## 新发现与下一步工程定义

1. **标记回读缺口。** 当前 description 可以写入，但现有 MCP fetch 不返回它。本次借只读界面排除对象身份未知后继续；这不证明无返回 ID 时的机器查找可靠。后续需验证可机器回读的标记承载方式或适配通道，不能把“创建成功”当作恢复机制完成，也不在本轮修改原库标记来掩盖问题。
2. **公式回读缺口。** 当前 MCP 返回公式引用而非数值，引用读取不受支持。Notion 本身实际算对，与机器校验通道不足是两件事。应补齐公式定义与实际数值的可靠读取方案；不得把模型算出的值写成平台回执。
3. **结论边界。** U01／U07 保留未关闭。关系、链接视图、排序、筛选、动态更新与小样例分页已取得当前环境证据；内部重试、完整范围枚举、真实故障接续、新 Agent、第二宿主、最终打包与完整六库产品验收仍未覆盖。

这次没有改变方法蓝图、评分或数据语义，也没有选定生产运行时。可以据这些实测结果针对性补工程定义，再形成完整实施计划。
