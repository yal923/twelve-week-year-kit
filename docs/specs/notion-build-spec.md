# Notion 可复现搭建工程设计

版本：0.1.0-review.4 · 状态：工程设计候选，尚非可运行安装包。

依据：[产品规格](v0.1-spec.md)、[数据约定](../data-contract.md)、Blueprint 1.0-portable.1 的 B04、B06–B09。本文补充工程职责、输入输出和验收边界，不重定义方法、计分或恢复语义。适用 R12、R14–R19、R21、R23。

## 1. 已确认目标与当前边界

所有者已选择“说明书＋预先写好的小工具”。首批为两位 Mac 使用者，分别使用 Codex 与 WorkBuddy，在独立 Notion 工作区运行。小工具负责固定结构、计算、校验和进度记录；Agent 负责个人引导、组织操作与解释结果。不建设开发者服务器，不集中收集个人数据。

使用者提供产品包，完成账号连接、指定新根页面及授权后，正常安装须自动完成。不得要求手工创建／修改字段、关系、公式、筛选、视图，或复制程序、输入命令来补齐安装。首次授权包含明确的私有日志位置和所需文件执行权限；不因“全自动”绕过宿主权限。

全自动约束针对正常安装。连接失效、越界、并发修改、未知请求结果仍按数据约定暂停或恢复；不得为完成安装而盲目重试。个人愿景、目标与承诺仍由本人通过对话选择，不能由安装器编造。

本轮仍是工程草案。最小宿主试验的局部事实与缺口见[两端能力对照](../../reviews/capability-comparison-2026-09-20.md)，不等于完整物理结构、共同小工具或正常安装已实现／实测；不能把本文交给 Agent 就声称能可靠安装。下列交付门槛用于收敛这些缺口，不授权当前创建产品运行时代码或新 Notion 内容。

## 2. 一致、完整、可恢复的含义

| 目标 | 必须相同或满足 | 允许差异 |
|---|---|---|
| 一致 | 同一发布版本、结构配置和已确认测试输入，对应相同的字段类型、选项、关系、视图条件、计分结果和状态转换 | 各实例随机 ID、Notion ID、创建时间；不参与规则的对话措辞和装饰 |
| 完整 | 结构清单全部建立并回读；方向、周期、周计划、记录、复盘、跨周期交接分别有可运行路径 | 真实安装可以是空白个人实例，不需要提前填真实目标或铺满 12 周任务 |
| 可恢复 | 新会话能从日志和 Notion 实际状态识别已完成、未完成及未知操作，继续安全步骤或给出明确阻断 | 不承诺所有错误无人介入，不承诺服务端事务、绝对不丢数据或自动回滚 |

结构通过和完整业务闭环通过是不同结论：空实例建立不证明个人计划已确认；虚构周期回放不证明真实 12 周效果。不同人的计划不比较文字相等；跨 Agent 复现测试使用同一组明确输入，不让两个模型各自发明目标后比较。

## 3. 组件职责与数据流

| 组件 | 输入 | 输出／边界 |
|---|---|---|
| 共同说明与引导 | 方法、已确认个人记录、当前请求 | 候选计划和待确认事项；不生成新的计分规则或私自改结构 |
| 结构定义 | 版本化机器可读清单 | 需要存在的页面、字段、关系、视图与正文格式；不含用户真实 ID |
| 共同小工具 | 结构定义、已确认配置、实际读取结果、进度日志 | 确定的差异／下一步动作、日期与分数、校验结果；同一输入可重复计算 |
| 宿主适配 | 获准动作与实际连接能力 | Notion 请求、真实响应、范围内回读和证据；不得自行降级为手工维护或改写共同语义 |
| 独立校验 | 预期定义、重新读取的实际结构／记录 | 逐项通过、失败、未验证及证据引用；不复用安装器“成功”的文字作为实际证据 |

依次为：包与环境检查 → 身份／范围检查 → 读取实际状态 → 生成动作清单 → 执行获准动作并回读 → 独立检查 → 安装结果。个人引导在结构准备好后保存答案，未授权时仍按引导协议 P01 形成对话草稿。

适配器优先使用用户已连接的宿主 Notion 能力，不读取宿主私有令牌来绕过工具接口。若需要其他连接方式、依赖或服务，先形成影响明确的方案，不能隐式引入。机器输入应来自适配器保存的实际响应和可追溯解析，不接受模型自行重写的“看起来正确”的结构摘要。无法可靠取得证据则报告未验证。

模型仍可能拥有其他工具权限，本文件和小工具不是安全沙箱；执行边界仍依赖宿主权限、范围检查与实际回读。所谓“独立校验”指独立读取和判定路径，不表示绝对没有软件缺陷。

## 4. 发布包中的确定性输入

以下是未来文件的职责，当前不创建这些运行时目录或空壳。

| 未来内容 | 必须完整定义 |
|---|---|
| `templates/notion/system.json` | 根页面入口、Profile、六库的 logical_key；属性、关系、视图、正文格式与安装依赖顺序 |
| `contracts/` | 所支持的数据／协议版本；字段与正文校验、未知值、唯一键、状态转换及输入输出格式 |
| `tools/` | 共同的计算、动作生成、进度管理、结果校验和比较工具；不可每次安装由 Agent 重新生成程序 |
| `adapters/codex/`、`adapters/workbuddy/` | 精确宿主能力映射、权限范围、返回值解析、错误／重试分类与自动视图操作 |
| `examples/`、`checks/` | 固定虚构输入、预期结果、结构比较规则和故障场景；期望值不由被测安装逻辑即时生成 |
| `VERSION.md` | 包／方法／协议／数据／结构版本及文件摘要；已验证的 macOS、芯片架构、宿主／连接版本与执行环境 |

一个发布包中的结构定义是物理安装的唯一输入，文档解释其含义，不维护两套可编辑物理定义。数据约定决定语义，结构定义必须承载它；两者冲突阻断发布，不能静默选一套。产品更新不自动迁移已有实例。

每个字段条目至少明确：逻辑键、显示名、所在库、Notion 类型、是否必填／可空、默认值、枚举及排序、谁可编辑、是否派生、验证规则。空值和未知原因按数据约定表达，不一律默认 0。

每个关系至少明确：源字段、目标库逻辑键、是否双向及反向字段、允许关联数量、同实例／同周期约束、创建依赖。不能只写“关联目标”；不能把旧实例平台 ID 固化进包。

每个视图至少明确：所属入口、源数据、布局、筛选表达式、排序与次级排序、显示字段顺序、空状态、选择周期／周的方法。筛选须绑定本实例、已确认周期和所选周；没有有效选择时显示空状态，不退化成全库。

每种结构化正文至少明确：记录种类、格式版本、定位标题／块规则、必填键与类型、空值规则、追加或替换范围、读取不完整时的处理。决定、交接索引、冻结基线、结算历史和修订记录均须覆盖；用户自由笔记不作为机器字段的替代品。

计算项必须指明唯一计算责任方。日期、half-up 评分和完整性判定由共同规则工具实现；Notion 若展示派生摘要，注明来源版本及更新时间，原始事实改变后须标为待重新核对，不能把过期摘要当作实时正确分数。任何必要的变更检测和展示方式都必须进入物理定义并实测。

本节规定了物理定义的完成标准，尚未冒充已提供完整 `system.json`。下一份可进入安装实现的技术交接必须逐项填实这些定义；缺字段、视图或正文规则时，安装任务不能进入执行队列。

## 5. 安装与交接接口

共同工具和适配器之间至少交换以下结构。格式须在实现前锁定，不能依赖自然语言总结传递结果。

| 记录 | 最低内容 |
|---|---|
| 安装请求 | 包及结构版本／摘要、host_profile、账号／工作区／根 ID、私有日志位置、授权范围引用；不含令牌 |
| 能力报告 | 所测宿主和环境版本、逐项能力 `verified / unsupported / unverified`、证据、权限边界；必需项非 verified 即阻断正式安装 |
| 动作计划 | instance_id、每步 operation_id、动作种类、对象逻辑键、父对象、依赖步骤、预期旧状态、目标值、写后断言与授权范围 |
| 实际回读 | 请求／操作引用、对象 ID、父位置、读取时间、平台更新时间、实际字段／关系／视图／正文、分页完整性与原始证据引用 |
| 校验报告 | 包与结构摘要、逐项检查 ID、预期／实际、`pass / fail / unverified`、证据引用、汇总结论和未解决项 |

未知能力的首次验证只能在另行明确授权的虚构测试根进行，不把未验证配置用于真实安装。正式安装只使用已验证的能力配置；临时连接权限仍须每次核对。

每步采用数据约定 §7 的 planned → in_flight → applied → verified 日志与 needs_attention 分支。写后断言包括父位置、身份、内容及所依赖关系；不能只根据请求返回成功码确认。重复运行先核对既有对象，已匹配部分不重建；差异项先分类，不将用户修改直接覆盖回发布定义。

断点不只记录“第几步”，还记录稳定键、实际 ID、版本、未知请求和下一步依赖。更换 Agent 后重读这些记录和 Notion 实际状态，不能凭上一个 Agent 的聊天总结直接继续写入。另一设备或宿主无法取得原私有日志时，须提供获准的日志交接或核对根页面恢复证据；无法还原未知操作则暂停，不新建空日志掩盖中断。

写入时若超出原授权、出现结构版本变化或竞争修改，停止相关批次。放弃旧尝试和新根重启仍按数据约定 §7.3，自动安装目标不改变该边界。首次安装不自动删除对象，不重建已有真实周期。

## 6. 两台 Mac 的能力门槛

首批目标只覆盖实际测试过的两套 Mac 环境；不能由“都是 Mac”推断所有 macOS／芯片或宿主版本都支持。尚未选择具体脚本语言或分发运行时，这个选择属于 U07，必须在工具实施计划获批前给出证据与明确方案。

运行时选择标准：宿主可在获准范围执行、所需版本可检测、无需使用者手工安装开发环境或配置命令、能够可靠写读私有日志，并满足两台 Mac 的平台限制。若必须添加新的运行时，先说明安装位置、大小、权限、来源和退出方式并按实际授权处理；不能把依赖下载藏在安装承诺里。不能通过让使用者开终端修复来判全自动通过。

自动设置并读取视图／筛选／显示列是必需能力；必要字段和正文读写、完整分页、身份标记、关系回读、未知请求不盲目重放、原始证据可供校验同样必需。任一项不足，标明对应环境不兼容并回到设计，不能保留 review.3 的视图人工兜底。

宿主可能要求操作权限确认。不得自动点击或绕过确认；若正常安装中还需要超出已约定授权流程的额外人工操作，记录实际次数与原因，不能声称该环境已经满足本版全自动目标。能力验证需覆盖这一点。

## 7. 跨 Agent 验收方法

对应 A25，并复用 A14／A17／A18。两次安装使用相同发布包及摘要、相同逻辑配置、固定虚构输入与指定观察时点；Agent 会话不携带开发聊天历史，测试位置彼此独立。操作者只提供包、账号连接、位置和范围授权，不临时教授字段或补写脚本。

至少包含四个分支：

1. 两个新 Agent 会话分别从空根安装；比较共同结构和同一虚构周期的结果。
2. Codex 与 WorkBuddy 在各自 Mac／工作区完成相同场景；同一宿主的两次安装不能替代此分支。
3. 同一实例重复运行：已核验对象不重复创建，不抹掉用户新增实际记录。
4. 在创建成功回读后、创建结果未知时分别中断，换新会话接手；前者安全续做，后者按数据约定 §7 的证据分支恢复或 needs_attention，不能把暂停报告为完整安装成功。

比较前先用对象标记验证实例归属、唯一性和实际关系；然后将平台 ID 映射回逻辑键，按清单排序，统一时间／数字表示。比较可排除平台生成 ID、操作时间与允许的装饰；不得排除关系目标、业务日期、实例隔离、过滤条件或缺失字段。映射冲突直接失败，不能通过归一化隐藏串库。

所有规定结构项都须通过同一预期定义；相同虚构输入的 D/N/U、状态、覆盖整数、决定采纳／观察和交接结果须一致。不要求模型解释文字完全相同，不比较真实用户愿景。校验器须能发现故意缺关系、错筛选、错计算和遗漏交接的测试实例，避免两个错误安装互相“证明正确”。

记录人工配置次数、开发者介入次数和未验证项；常规安装人工配置／临时开发者补充指令均须为 0。存在任何必需项 fail／unverified，不发布完整通过结论。测试记录和真实映射留在本人私有位置，公开报告只放脱敏结果。

## 8. 工程准备状态与后续交付门槛

| 内容 | 当前状态 | 完成证据／阻断点 |
|---|---|---|
| 全自动、工具包、两台 Mac、review.3 基线 | 用户已确认 | 已进入 C06–C09；不是实现授权 |
| 本文的组件、接口和复现标准 | 设计候选 | 所有者审阅具体版本；冲突按语义权威顺序处理 |
| 两宿主能力与执行环境 | U01／U07 部分取证，尚未通过 | Codex 有直接实测，WorkBuddy 摘要报告数字写入阻断；补齐版本与原始请求证据、解决共同回读／重放缺口，再决定适配和必要补测 |
| 完整物理定义与适配操作映射 | 尚未交付 | §4 每一项有具体值，§5 接口有可解析格式；不允许安装任务靠临场补定义 |
| 安装／计算／校验工具与双宿主测试 | 尚未实现 | 完成批准的实施任务，A01–A25 的适用证据齐全，尤其 A25 独立搭建与接续 |

推进顺序是工程设计审阅 → 获准的最小能力验证 → 锁定物理定义／运行环境和具体实施计划 → 实现与独立验收 → 两人试用与分发。能力验证自身的测试步骤与写入范围也须先具体化并获准；不能以“只是验证”为由先建 Notion。

方法承载不变：B04 的行动定义／周执行用独立记录和 A07 验证；B06 用共同计分工具及 A08–A11；B07–B09 用结构化决定、观察和交接及 A12／A13。本文引入工程可复现性，不把程序包、六库或自动安装说成原著要求。
