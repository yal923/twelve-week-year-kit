## 0. 所有者先看这里

目标保持原样：两位使用者各自在自己的 Mac 和 Notion 运行同一个产品包；Agent 帮助选择个人目标，共同工具负责固定结构、读写检查与恢复。当前补丁解决“执行时临场改参数、改步骤、少记尝试，以及检查缺失后继续”的问题。

本轮交付的是以下设计，而非可运行软件：

1. 一个动作从提出到验证的明确规则与数据格式。
2. 小工具、Agent 和宿主连接各自承担什么，以及哪些保证目前做不到。
3. 一个单记录、单数字字段的诊断范围候选。
4. 审核与未来验证清单；真实能力不足时明确停在哪里。

**所有者只需审阅范围与使用影响，无须填写接口参数。** 本轮推荐沿用现有连接，先验证固定映射和可观察边界；不选择新服务、不安装运行环境。若现有连接不能满足必要能力，再提交具体替代方案。接受本文也不等于批准女朋友账号上的写入，她需在本侧核对具体对象后确认自己的范围。

用户体验保持：先建立可核验的空系统，再逐步引导并保存愿景、目标与计划；愿景允许暂不完整。工程动作预算约束一次具体批次，不限制一个人能创建多少目标或使用多少周期。

全文中“必须”描述候选契约获批后的要求，不赋予本文当前执行权限。

## 2. 推荐路径与执行边界

| 路径 | 工作方式与代价 | 本轮处置 |
|---|---|---|
| 现有宿主连接＋共同工具 | 工具生成确定参数、验证证据与计算下一步；宿主调用现有连接。无需新增账号连接，但必须验证真实调用／回执能否直接交给工具核对 | 推荐先研究并验证；仍是候选 |
| 由共同工具直接持有独立连接并派发 | 更容易让计数、请求与传输处于同一程序路径；会引入新连接、授权与运行时问题，且平台功能覆盖未验证 | 保留为能力冲突后的备选，当前不选择、不读取已有令牌来实现 |

仅增加 Prompt 不能代替 C07 的共同工具。第一条路径也不能声称强制拦截所有模型操作：Agent 若仍拥有其他写工具，可能绕开本地检查。正式支持该路径前，须做到：工具覆盖计划内动作的准备与核验；宿主实际调用轨迹可与动作清单逐项对账；额外调用使流程符合性失败。若取得实际轨迹或原始回执只能依赖模型重写，停止正式适配，不将其包装成机器校验。

|---|---|---|
| 引导 Agent | 理解用户意图、提出候选、请求必要确认、解释停止原因 | 临时改字段类型、完成标准、重试次数或测试值 |
| 共同工具 | 参数校验、动作预算、日志状态、差异计算、写后断言与报告 | 推断个人愿景；把希望写入的值当实际回读 |
| 宿主适配 | 映射真实工具名、传递已确定参数、直接捕获调用与响应、执行限定读取 | 从文字“成功”重建伪原始响应；猜测隐藏请求 |

## 3. 私有记录契约

以下名称是逻辑记录，不要求新增数据库；均保存在本人已批准的包外私有日志位置。未来编码使用可解析 JSON／JSONL，确切运行时在 U07 关闭前确定。本节固定字段含义，不创建空运行时目录。

| 记录 | 必需字段与类型 | 约束 |
|---|---|---|
| Run | run_id、instance_id、package_version、contract_version、host_profile_ref：非空字符串；created_at：带时区时间；authorization_ref：引用 | 新诊断使用新 run_id；复查旧实例时保留它原有 instance_id，不改远端标记 |
| HostProfile | host_name、版本观测来源／时间、tool_schema_ref、tool_schema_sha256、connection_ref、capture_mode；隐藏重试状态及依据 | 版本不可得为 null＋原因，不能将事后版本冒充运行时；schema 摘要不证明隐藏实现没有变化 |
| Authorization | approval_ref、scope_version、账号／工作区／根引用、允许动作和精确目标、字段允许集、写入预算、只读范围、可选例外及有效状态 | 审核报告不是批准。内容变化须形成新版本；未来需用户输入的真实 ID 只在私有实例中绑定 |
| Operation | operation_id、action_kind、target_ref、parent_ref、dependencies、preconditions、desired_patch、postconditions、authorization_ref、request_artifact_ref | 表示一个逻辑动作；生成后不可改目标／字段／值来掩盖另一种动作 |
| Attempt | attempt_id、operation_id、ordinal、request_sha256、state、timestamps、dispatch_evidence_ref、receipt_ref、outcome、no_effect_evidence_ref | 每次主动派发一个新 attempt；operation_id 不是远端幂等键；调用时间无真实来源时 null＋原因 |
| Evidence | evidence_id、origin、captured_at、raw_artifact_ref、sha256、completeness、source_call_ref | origin 为 actual_dispatch / tool_response / readback / ui_transcription / inference；后两种不得冒充机器回执 |
| Check | check_id、operation_id、expected_ref、actual_evidence_refs、status、reason | status 为 pass / fail / unverified；缺证据为 unverified，不填预期值 |

`ref` 须能解析到该实例的实际持久记录；示例别名不是可派发 ID。模板不含作者账号／页面映射。`null`、字段未返回与读取截断分别表达；后两者不当作“已知为空”。时间表示不变更 Cycle 的时区与周界规则。

## 4. 参数准备与类型检查

执行输入来自获准动作和实际 schema，而不是模型再次复述。共同工具生成 UTF-8 请求文件，计算该文件实际字节的 SHA-256，存入 Attempt；适配器引用该文件并保存宿主实际派发参数。哈希只证明本地文件版本，**不证明宿主或服务端收到了相同字节**。宿主 JSON 重排键不算业务差异，但解析后必须类型与值相同，不能把字符串转成数字后再比较。

字段操作明确区分 `set(value)`、`clear(null)`、`leave_unchanged`。未列入 desired_patch 的字段不得写入；clear 只在字段可空且授权明确时允许。无效值在派发前拒绝，不靠远端试错。

| 类型 | 派发前断言 | 遇错行为 |
|---|---|---|
| number | JSON number，有限值；整数要求、范围、单位来自具体字段定义；boolean、数字字符串不合格 | 本地拒绝；不自动转字符串或改成其他数字 |
| relation | 指向当前实例已核验记录；数据库／data source／页面 ID 各有类型 | 无映射、错实例或错对象类型即阻断，不按同名搜索猜目标 |
| select / status | 是发布结构列出的选项 | 不临时新增选项 |
| 日期／正文 | 符合已有数据语义和版本化格式 | 不用设备时区覆盖周期时区，不用自由文本替代机器字段 |

创建动作须一次携带该对象的稳定身份和本步骤要求的初始内容。“创建含数字记录”失败，不自动改成“先建空记录再更新”；这会变更动作图、授权预算和检查点。既有安装若因平台依赖明确采用分步操作，每一步必须在原计划中列出，不是禁止所有预先设计的分步安装。

## 5. 派发预算与前置条件

每个已批准批次有 `max_total_write_attempts`、各 action_kind 上限和每个 Operation 的 `max_attempts`，均为非负整数；**默认 max_attempts=1，未列出的写动作预算为 0**。本地解析拒绝不消耗远端派发次数；只读调用另记，不混入写入次数。

派发前先追加 planned，再检查下列项目；全部通过后持久化并回读 in_flight 与预算占用，才交给宿主：

1. 阶段和本次授权有效，目标、字段及值属于该清单。
2. 当前连接身份和父位置匹配，日志与原始证据通道可用。
3. 所依赖 Operation 已 verified；所需标记／关系／内容证据齐全。
4. 新读取的关键前态及平台更新时间与计划快照一致；单写入者条件成立。无服务端原子性时，仍保留读取与写入间的竞争风险并写后检测。
5. 参数／schema 检查通过，动作与整个批次均有剩余预算。

预算报告同时给出：`reserved`（已写 in_flight）、`observed_dispatches`、`succeeded`、`rejected`、`unknown`。有效占用取每个预留 attempt 与未登记实际调用的并集，不能只按成功数量算。400／失败仍消耗已派发预算；结果未知也占用。崩溃留下的 in_flight 默认保留占用；只有可靠证据证明未派发，才能追加释放事件，不删除原日志。

意外的未登记写调用先记录为偏离并计入实际次数，停止余下写入；不得事后补一个授权条目让总数合格。工具看不到真实调用时须注明无法对账，不声称预算被强制执行。托管内部重试与主动派发数分栏；隐藏内部次数未知时，不用“主动调用一次”推导“服务端只执行一次”。

## 6. 结果判定与停止分支

沿用数据 §7 的 operation 状态：planned → in_flight → applied → verified；异常进入 needs_attention。Attempt.outcome 另记 not_dispatched / succeeded / rejected / unknown，不用新状态替换数据约定。

| 观察到的情况 | 必须记录／执行 | 是否继续依赖写入 |
|---|---|---|
| 本地前置检查失败 | 不派发，保存失败断言 | 否 |
| 工具返回成功／对象 ID | 保存原始回执，进入 applied；独立读取身份、父位置与关键内容 | 只有所有必需断言通过后才允许 |
| 返回 async_task | 保存句柄，沿同一 attempt 只读查询状态；非终态不等于已写成功 | 等到成功并独立回读后才允许 |
| 返回 400、权限错误或其他拒绝 | 保存完整错误，outcome=rejected，进入 needs_attention；不推定整体无副作用 | 否，不自动更换参数／拆分请求 |
| 超时、丢响应、回执不可保存 | outcome=unknown，保留 in_flight 事实并标 needs_attention，按数据 §7.2 只读查证 | 否，不主动重发 |
| 回读缺标记、截断、缺字段、仅公式引用 | 检查 unverified；记录缺口，不能填入请求值或心算公式值 | 否 |
| 回读值／关系不符或出现额外写调用 | 检查 fail，保留实际状态和差异 | 否，不自动覆盖回旧值或清理 |

正式安装所需的库标记仍按数据 §7.1 核验；请求里含标记并不足够。公式表达式和实际值是两项检查。读取通道不能解析引用时保留缺口；只读界面观察单列，不直接升级为机器适配通过。

异步监测不产生第二次写调用。所有可返回异步结果的映射必须定义最大查询次数与观察窗口，并尊重实际响应的最小建议间隔；达到任一上限即停止发起新查询并保留 needs_attention。已发起读取的实际耗时可能超过窗口，须如实记录，不承诺宿主一定能立即取消调用。窗口到期不证明任务取消或未执行，也不能重新提交原写入。具体诊断的数值见 §8。

目前没有适用于这两套连接且已验证的“无副作用错误可重试”白名单。本候选将自动写重试集合设为空。以后增条目须同时具备数据 §7.2 所要求的宿主／平台依据、验证和剩余原授权预算；本人批准更大次数也不能把未知结果变成可重发。

## 7. 接续与报告

新会话首先重读 Run、授权、版本、全部未结算 Attempt 和最新实际状态，随后依序处理：

- verified 对象匹配：直接复用；实际已被用户修改：按数据 §6 处理差异，不能自动重新安装覆盖。
- applied 尚缺核验：只读补核验；缺少原始回执仍如实标记，不补造。
- in_flight／unknown：依数据 §7.2 找回或停止；是否能证明未派发以真实轨迹为准。
- 未派发且依赖已满足：只有在原范围及剩余预算内才可生成下一次准备记录。

报告分别给出功能结果、证据完整性、按计划执行、恢复覆盖；任一必需项 fail／unverified，不合并成“安装通过”。被测预期、真实请求、独立回读与校验结果有不同引用，禁止一个模型生成的“成功 JSON”同时充当四者。

## 8. 数字诊断范围候选 NUM-01

### 8.1 问题与对象

本次只回答：**在当前宿主上，按固定映射更新一个既有虚构记录的 number 字段，真实派发参数是否保留数字类型，能否独立读回目标值？** 即便成功，也不证明间歇性问题消失、创建含数字记录通过或双端兼容通过。

优先在 WorkBuddy 侧进行；当前 Codex 不访问她的账号。对象限定为该侧旧探针中已成功补写的 `W1A`，字段 `ProbeValue`，要求当前值仍为 JSON number `2`，目标值为 JSON number `5`。`Week=1`、`Order=10`、Name、Goal 关系、instance_id、record_id、父 data source 保持原值。真实 ID 从该侧原私有映射读取并由账号持有人确认；缺映射、前态改变或对象不符时停止，不选择另一行代替。还须读取旧尝试记录，确认没有涉及此对象的在途或结果未知写入，且当前没有另一写入者；无法确认则停止，不能靠本次例外消除旧请求的不确定性。

### 8.2 数量与权限边界

| 动作 | 主动派发上限 | 限定范围 |
|---|---:|---|
| 新建库／记录／视图；改 schema／正文；删除／还原 | 0 | 本诊断不包含这些动作 |
| 更新页面属性 | 1 | 仅 W1A.ProbeValue：2→5，不能再写一次 2 来恢复 |
| 前置 Notion 只读调用 | 6 | 当前身份、指定根、映射中的库／data source、W1A 前态与必要的临写前复查；不足以核清即停止，不扫描工作区 |
| 写后读取同一 W1A | 2 | 成功、错误或未知后都只作观察；两次不一致须保留并标 unverified，不能挑符合预期的一次 |
| 同一异步任务状态读取 | 3 | 仅实际返回的句柄；从拿到句柄起 30 秒内最多发起三次查询，等待至少实际建议间隔，未提供间隔则为 2 秒；下一次等待将超出窗口时不再发起查询 |

这将最多主动派发一笔写请求，**不保证托管服务内部只执行一次**。前置读取和临写前读取合计受六次上限约束；本地读取日志和已暴露工具声明不计 Notion 调用，但不得借此读取凭证或全机配置。

可用现有映射直接取到对象身份不等于 description 标记已经验证。由于旧试验该项仍缺，本候选提供两种明确处置：

- **默认只读处置：**未取得该侧新授权，或仍缺正式前置证据时，最多提出读取／停止报告，不派发诊断写入。
- **待本人选择的单次诊断例外：**仅对已确认的既有 W1A，允许以直接页面 ID、匹配的记录稳定键、完整父链和当前前态作为这一次属性修改的身份依据，同时明示 description 回读与托管内部重试仍未验证。它不放行任何创建、身份找回或后续依赖写入，不证明原试验符合计划，不修改正式安装的标记与重试门槛。该侧须明确接受这两项缺口及“一次主动派发、无自动恢复”的范围；旧例外不能继承。

只读范围也须属于该侧本次授权；本文件发布本身不授权读取她的账号。不接受例外或前态核对不足即停，不将沉默、批准文档或已收到文件视为同意测试。

### 8.3 请求、回读与异常

以下是来自既有工具形状的**脱敏请求候选**，不是已调用回执；执行前须核对当时实际工具声明。`ROW_W1A` 必须通过该侧获准映射绑定，任何未解析别名禁止派发。若当前声明不兼容，先修订映射并复核范围，不在线猜参数。

```json
{
  "command": "update_properties",
  "page_id": "ROW_W1A",
  "properties": {"ProbeValue": 5},
  "allow_async": false
}
```

工具对应接收侧曾报告的 `notion-update-page`；同名并不证明版本／行为相同。保存本次工具声明、当前宿主版本及其来源。派发前持久化请求、授权、in_flight 与预算；真实调用参数及真实响应须经已验证通道直接保存。尚未实现共同工具时，只能在另行获准的诊断执行安排中逐项核对，不宣称本文已提供强制控制。

`allow_async=false` 不被当作“绝不会返回异步句柄”的保证；如返回 async_task，按 §8.2 的有限查询处理，终态前不宣称成功。任何拒绝／超时后不再次写入、不改 5 为字符串、不增加其他数字字段、不重新创建记录。

写后比较 ProbeValue 是否为 number 5，同时检查前述非目标字段及父位置未改变。修改时间、Double 等平台派生结果可能变化，单列观察，不要求与旧值相等；公式引用不可解析不阻止这个仅数字属性的局部判定，但必须明确公式能力未测。即便观察到 ProbeValue=5，若调用结果未知或证据不完整，也只能记“观察值符合、操作未完整核验”，不能补造成功回执。

默认一次写后读取即可；仅当响应不足以判断时，允许在总上限内再只读一次。读取窗口内仍不明确即停止，后续恢复只读可另行提出。两次读取都必须保留。测试值 5 保留在原虚构记录中，原能力报告保持原观察时点；不再把这个实例当作未经改变的原固定输入。

### 8.4 输出与结果分支

该侧私有目录保存新的 Run、前态、请求、真实派发／响应、写后读与尝试账本。公开只返回 `numeric-diagnostic-summary.md`：版本来源、预期／实际类型和值、主动派发数、隐藏重试状态、是否使用本次例外、原始证据是否完整，以及未验证项。保持稳定脱敏代号，不自动发送给开发者。

| 结果 | 下一步 |
|---|---|
| 前置不足，未派发 | 输出 blocked 和确切缺口，补适配设计；不通过换对象来继续 |
| 实际派发参数已变成字符串 | 记录已观察到的边界差异；只定位到最早有证据的环节，不反推其上游实现 |
| 参数仍为 number，但拒绝且无下游请求体 | 保存错误，故障层仍未知；另行评估可观察通道，不能归咎某厂商 |
| 成功回执＋可靠独立读取为 5＋其他断言满足 | 仅本次单字段更新 pass；下一阶段才设计创建含数字及稳定性验证，不立即扩展试验 |
| 值不符、额外写调用或未知结果 | 功能／执行符合性分别报告，保留对象与日志，停止 |
