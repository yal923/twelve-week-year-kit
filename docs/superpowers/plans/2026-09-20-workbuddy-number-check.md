# WorkBuddy 数字读写小测试｜NUM-01

版本：NUM-01.1 · 日期：2026-09-20 · 状态：计划已准备，尚未执行。

> **执行方式：**由接收方自己的 WorkBuddy 在本会话顺序执行，不分派其他 Agent。本文件自包含，可单独发送，不需要整个仓库或安装 Superpowers。编写采用 writing-plans；在已具备 Superpowers 的开发环境中执行时使用 executing-plans，接收方按下面清单执行即可。

**Goal：**验证当前连接能否读取一条已知虚构记录，并将一个 number 字段正确更新、独立读回；不预设故障来自连接不稳定。

**Architecture：**复用上次测试的 W1A；先只读检查，再由本账号持有人确认一次具体写入，最后只读核验并报告。一次主动更新，不自动重试或还原。

**Tech Stack：**当前 WorkBuddy、已连接的 Notion 工具、已有本地文件能力。无新连接、依赖或订阅。

**Spec：**[EP-01-draft.1 第 8 节](https://github.com/yal923/twelve-week-year-kit/blob/e9e4156e3c68c417e99d6226c149d42adf676403/docs/superpowers/specs/2026-09-20-notion-execution-patch-design.md)。本文件完整承载该诊断范围；来源链接只作追溯，接收方不必另读整个设计。开发者本轮明确要求编写此小方案，不代表全产品实现或该侧写入已经批准。

## Global Constraints｜本次只做这些

- 目标：原虚构记录 **W1A**；字段 **ProbeValue**；**数字 2 → 数字 5**。不把 5 写成字符串。
- 写调用上限 **1 次**；不新建库／记录／视图，不改 schema、关系、正文或其他字段；不自动还原为 2。成功、报错、超时都不能自行再写一次。
- Notion 前置只读调用最多 **6 次**；写后读取同一记录最多 **2 次**；若出现异步句柄，对同一任务最多 **3 次**只读查询，发起窗口为取得句柄后的 **30 秒**。
- 不搜索整个工作区，不读取凭证，不重新运行上次整包。原报告和原日志不改；测试后保留新状态。
- 文件本身不是账号授权。账号持有人在本会话要求“按这份方案复测”后，才开始限定的本地及 Notion 前置读取；写前按 Task 2 核对并取得本次具体确认。
- 任一步阻断，都跳到 Task 4 生成真实摘要，不继续依赖它的写入；即使零写调用，也应交回结果。

## Review Focus｜需要分清的五种情况

| 情况 | 对应步骤与处理 |
|---|---|
| 身份或页面读取失败 | Task 1：记为前置读取阻断；数字写入尚未测试，不统称数字功能坏了 |
| 记录错了、数字不再是 2、有旧请求未决 | Task 1：停止，不换记录或修改测试值来迁就现状 |
| 请求被转成字符串、无法保存实际请求／回执 | Task 2：保存可观察边界；无可靠证据通道时不派发 |
| 报错、超时或仍在异步执行 | Task 3：不重发；只在限定范围观察，保留未知 |
| 返回成功但读回错误、缺失或前后两次不一致 | Task 3–4：不能判通过；保留全部结果，不挑符合预期的一次 |

## Task 1：找到原记录并检查读取

**Files：**只读上次 run.json、映射和相关操作日志。在原运行目录的相邻私有位置新建本次目录，名称含新的随机 run_id；保存 run.json、operations.jsonl、evidence/ 和最终 numeric-diagnostic-summary.md，不覆盖旧文件。

**Interfaces：**输入为原私有映射和本人本次读取指令；输出为有来源的账号／对象身份、字段 schema、前态与阻断原因。

- [ ] 记录当前 WorkBuddy／macOS 版本及来源、实际 Notion 工具名和输入声明；拿不到的写 unknown，不读取私有连接配置。
- [ ] 从旧映射找到 W1A 的真实页面、data source、数据库、根页面及记录稳定键；检查没有涉及该对象的在途／未知写入。缺映射或仍有未决请求就停止，向本人说明缺什么。
- [ ] 使用当前实际工具声明，最多六次前置调用核对：当前身份、原指定根、数据库、data source、W1A 前态及临写前复查。数据库 ID、data source ID 和页面 ID 不混用；完整父链、instance_id、record_id 均须与原映射匹配。六次不足以确认则停止，不扩查。
- [ ] 确认 ProbeValue 为 number 且当前为 2；Week=1、Order=10，并保存 Name、Goal 关系、稳定键、父位置与更新时间。缺字段／截断不当作空值；前态不符就停止。
- [ ] 将实际只读工具响应直接保存并独立重读，确认原始证据通道可用。模型转述、手写 JSON 不算原始回执；通道不可用就不写入。保存当前读取结果，不推断写权限也已通过。

## Task 2：确认范围，准备唯一一次更新

**Files：**在本次 run.json 保存本人确认及范围，在 operations.jsonl 保存本次动作／尝试，在 evidence/ 保存实际前态、确定参数和后续真实回执。

**Interfaces：**输入为 Task 1 的匹配结果；输出为明确获准的单字段请求。任何条件缺失则输出 blocked，零写调用。

- [ ] 向本人展示实际账号、W1A 页面入口和“ProbeValue 2→5，只主动更新一次，结果保留，不自动恢复”，并确认该记录没有其他人在同时编辑。
- [ ] 同时说明上次数据库 description 标记无法读回、托管内部重试行为仍未验证；本次仅用已确认页面 ID、记录稳定键、完整父链和当前前态核对这个既有记录，不验证建库／缺 ID 找回。请本人一次明确确认接受这些缺口下的单字段诊断。旧例外不可继承；不同意则仅报告已读结果。最多一次主动调用不等于保证服务内部只执行一次。
- [ ] 核对当前工具声明仍支持下方形状。将 ROW_W1A 绑定为刚核对的真实页面 ID；未解析别名不能派发。工具声明不兼容时停止并说明差异，不猜参数。

```json
{
  "command": "update_properties",
  "page_id": "ROW_W1A",
  "properties": {"ProbeValue": 5},
  "allow_async": false
}
```

- [ ] 保存准备请求及文件摘要，确认 5 为 JSON number。记录 operation_id、attempt_id、授权引用、目标／父对象、前态、请求、planned；临写前复查计入六次预算。前态或更新时间变化则停。
- [ ] 派发前追加并回读 in_flight 和“一次写入预算已占用”。实际调用时间只取真实工具轨迹，拿不到就 null＋原因。没有可靠保存这些信息，不派发。

## Task 3：写一次，独立读回

**Interfaces：**输入为获准请求；输出为真实调用、响应和独立读回结果。只用当前实际工具名，不照抄其他宿主的名字。

- [ ] 主动调用一次页面更新工具，保存实际发出的参数／类型和完整响应或错误。准备请求与实际派发分开留证；看不到的下游请求体明确写未观察到，不依据错误重建它。
- [ ] 若返回 async_task，即使 allow_async=false，也保存句柄；每次等待至少响应建议间隔，未提供时等 2 秒。最多查询三次，且不在取得句柄 30 秒后发起新查询。非终态、调用超时或窗口结束时保留未知，不再次提交更新，不声称任务已取消；已发起读取的实际耗时可以超过窗口，须记录。
- [ ] 成功、拒绝或结果未知后，都可独立读取同一 W1A 一次；响应不足以判断时最多再读一次。若任务仍未完成，读到值也只作观察，不能当终态成功。
- [ ] 检查 ProbeValue 是否为 number 5，且 Week、Order、Name、Goal、稳定键和父位置未改变。更新时间和 Double 等派生值可能变化，单列观察；本次不验证公式，不把不可解析的公式引用当数字写入失败。
- [ ] 遇到任何错误，不重试、不改字符串、不改其他数字、不新建替代记录、不清理。400 也计为一次已派发；不推断该工具完整路径必然无副作用。若发现额外主动写调用，报告实际次数和偏离，立即停止后续写入。

## Task 4：只交回这一份脱敏摘要

**Files：**生成 numeric-diagnostic-summary.md，放在本次私有运行目录，向本人报告完整路径；由本人决定转交，不自动发送。真实 ID／账号／页面链接／原始回执留本机。

- [ ] 按下面各项填写实际结果；未发生就写未测试／未观察到，不填假值。
  - 计划版本 NUM-01.1；运行日期、宿主／系统版本及来源、工具名／可见版本。
  - 前置读取：通过或具体阻断；number schema、原值及类型。
  - 本次确认：是否接受单次诊断例外；只保留结论，不公开私人确认原文。
  - 实际主动写调用次数；成功／拒绝／未知分别几次；如未派发，明确为 0。
  - 脱敏实际请求参数与 JSON 类型；原始错误 code／message；下游请求体是否真的观察到。
  - 异步任务是否出现、实际查询次数／状态；隐藏重试仍未知时如实保留。
  - 独立读回的数值／类型、非目标字段是否一致；完整原始证据是否保存，证据代号对应什么。
  - 结论：pass / fail / unverified / blocked，原因，以及改后值是否保留。
- [ ] 仅当成功回执或异步终态成功、独立回读 number 5、非目标断言通过且证据完整，记本次数字更新 pass。返回拒绝／明确值不符记 fail；结果未知或证据不足记 unverified；未派发记 blocked。按计划执行另列 pass / fail / unverified，不与功能结果混成一个勾。
- [ ] 读取成功、写入失败，只能说明只读路径可用而本次写路径失败；单次成功也不能证明间歇性故障已修复、创建数字记录通过或整套系统兼容。保留实际测试值，不自动还原或安排下一次试验。
